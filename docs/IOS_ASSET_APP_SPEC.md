# iOS 资产管理 App — Codex 开发说明书

> 目标：参考用户提供的「有數」资产管理 App 截图，开发一款原生 iOS 资产管理应用。本文档可直接作为 Codex 的项目需求与实施指令。  
> 说明：参考截图用于学习布局、信息层级和交互方式；请重新设计图标、插画、品牌和细节，不要直接复制原 App 的商标或专属素材。

## 1. 项目目标

开发一款简洁、精致、以「物品资产生命周期成本」为核心的 iOS App。用户可以记录购买的物品、购买日期和价格，应用自动计算持有天数、日均成本，并通过资产列表、详情页和统计页面帮助用户了解消费与使用价值。

### 核心原则

- 原生 iOS 体验，优先使用 SwiftUI。
- 支持浅色模式，适配不同尺寸 iPhone。
- 视觉风格：浅灰背景、白色圆角卡片、黑色主文字、绿色强调色、柔和阴影。
- 首版离线可用，数据保存在本地；不强制登录、不依赖服务器。
- 结构清晰、可测试、可扩展，不把全部逻辑写在一个 View 中。
- 先完成可运行的 MVP，再迭代动画、图表、导出和备份功能。

## 2. 技术方案

- 平台：iOS
- 语言：Swift
- UI：SwiftUI
- 最低系统版本：iOS 17（若项目环境不支持，可降至 iOS 16 并调整 API）
- 本地存储：优先 SwiftData；如果目标系统或工程模板不适用，可使用 Codable + 文件持久化。
- 图表：Swift Charts
- 日期与金额：使用 `Calendar`、`DateFormatter`/`FormatStyle`，金额显示人民币 `¥`。
- 架构：MVVM；数据模型、业务服务、视图分层。
- 测试：为成本计算、持有天数、资产状态和汇总金额编写单元测试。

## 4. 功能需求

### P0：首版必须完成

#### 4.1 资产管理

- 新增资产、查看详情、编辑资产、删除资产。
- 资产字段：
  - `id`
  - `name`
  - `price`
  - `purchaseDate`
  - `category`
  - `status`
  - `kind`（asset / wishlist）
  - `iconName` 或图片引用
  - `notes`
  - `tags`
  - `createdAt`
  - `updatedAt`
- 状态：
  - `inUse`：使用中
  - `retired`：已退役
  - `sold`：已卖出
- 支持资产/心愿切换。
- 默认按购买日期或最近更新排序，并支持按名称、价格、日均成本排序。

#### 4.2 成本计算

按天计算的默认公式：

`日均成本 = 购入价格 ÷ 持有天数`

- 持有天数最少按 1 天计算，避免除零。
- 日期按自然日计算，避免时区造成日期偏移。
- 对于已卖出物品，第一版可继续按购入价格计算；后续可增加卖出价格，计算净成本。
- 退役物品默认仍累计持有天数；可在后续设置中增加“退役后停止累计”的选项。
- 按次模式需要用户记录使用次数：
  `单次成本 = 购入价格 ÷ 使用次数`
- 自定义模式允许用户输入一个目标成本或自定义分母规则；若需求不清楚，首版先提供按天模式，并把其他模式作为可扩展接口。

#### 4.3 总览统计

- 总资产购入金额：统计资产类型，不包括心愿。
- 日均成本：建议默认显示“全部有效资产日均成本之和”，并在 UI 中标注口径。
- 使用中/已退役/已卖出数量。
- 状态占比进度条。
- 空状态：引导用户新增第一件资产。
- 搜索：按名称、类别、标签搜索。

#### 4.4 心愿清单

- 添加心愿：名称、预计价格、类别、备注。
- 心愿不计入已购资产总额和实际日均成本。
- 支持标记为已购买，并转换为正式资产，要求补充实际购买日期。

#### 4.5 趋势页

- 按月显示资产购入金额、累计购入成本、当前日均成本趋势。
- 首版可用 Swift Charts。
- 无数据时显示空状态，避免绘制误导性图表。

#### 4.6 设置页

- 货币单位：首版固定人民币，后续扩展。
- 数据导出：导出 JSON 或 CSV。
- 数据备份与恢复：首版至少支持 JSON 导出；导入前进行数据校验。
- 隐私说明：数据默认只存储在本机。
- 清空数据：必须二次确认。

### P1：后续迭代

- 资产照片与相册选择。
- iCloud 同步。
- 使用次数记录与提醒。
- 卖出收入、维修费、耗材费，计算净生命周期成本。
- Face ID / Touch ID 应用锁。
- 小组件与快捷指令。
- 多币种。
- iPad 自适应布局。

## 5. UI 规范

### 5.1 色彩与样式

- 页面背景：接近系统浅灰（例如 `#F5F5F7`）。
- 卡片背景：白色。
- 主文字：近黑色（例如 `#171717`）。
- 次级文字：中灰色（例如 `#8A8A8A`）。
- 强调绿：明亮但不刺眼（例如 `#9BE52E`）。
- 错误/删除：柔和红色。
- 卡片圆角：24–30 pt。
- 主按钮圆角：胶囊或 16 pt。
- 使用系统字体与 SF Symbols，不依赖外部图标库。
- 动画克制，减少大范围弹跳；列表、筛选和保存可使用轻量动画。

### 5.2 资产卡片

卡片信息优先级：

1. 名称与状态
2. 日均成本
3. 购买价与持有天数
4. 图标/照片

价格和日均成本都要使用统一的人民币格式，例如 `¥3,221.98`。价格小数位统一为 2 位；列表中的日均成本也统一两位小数。

### 5.3 可访问性与适配

- 支持 Dynamic Type。
- 所有图标按钮添加 accessibilityLabel。
- 不能只用颜色表达状态，还需显示文字。
- 适配安全区与底部 Home Indicator。
- 键盘弹出时表单可滚动，保存按钮不能被键盘永久遮挡。
- 使用 `NavigationStack` 和系统手势返回。
- 页面不能出现横向溢出；长名称最多两行，必要时截断。

## 6. 数据模型建议

```swift
enum AssetStatus: String, Codable, CaseIterable {
    case inUse
    case retired
    case sold
}

enum AssetKind: String, Codable {
    case asset
    case wishlist
}

enum CostMode: String, Codable {
    case perDay
    case perUse
    case custom
}

struct Asset: Identifiable, Codable {
    var id: UUID = UUID()
    var name: String
    var price: Decimal
    var purchaseDate: Date
    var category: String
    var status: AssetStatus
    var kind: AssetKind
    var costMode: CostMode
    var useCount: Int
    var iconName: String
    var notes: String
    var tags: [String]
    var createdAt: Date
    var updatedAt: Date
}
```

实现时请注意：

- 金额使用 `Decimal`，避免用 `Double` 进行货币精度计算。
- 持有天数计算时使用 `Calendar.current.dateComponents([.day], from:to:)`，并确保至少为 1。
- SwiftData 模型需要遵循其持久化约束；如果 `Decimal` 或复杂枚举持久化遇到问题，可将枚举存储为 `String` 并在业务层转换。
- 模型字段默认值和迁移策略要明确。
- 不要把格式化后的金额字符串存入数据库。

### 代码质量约束

- 禁止把所有功能写在单个 Swift 文件。

- 避免强制解包；合理处理空数据和异常输入。
- 业务计算与 UI 分离。
- 所有按钮必须有真实行为，不能只做静态展示。
- 不使用虚构数据冒充用户真实数据。可提供明确标注的演示数据，并允许一键清除。
- 删除、清空和导入覆盖操作必须确认。
- 不得未经用户同意上传资产数据或添加第三方追踪。
- 对文件导入执行格式和字段校验。
- 提供合理的错误提示和空状态。

## 12. 需要注意的产品定义

- “资产总额”在本 App 中指历史购入成本总和，不代表当前二手市场估值。
- “日均成本”是购入价格除以持有天数，不代表会计折旧或市场价值。
- 退役物品是否继续累计持有天数应在产品中明确说明。
- 没有真实历史记录时，趋势图只能展示可推导指标或按月汇总，不能伪造每日历史值。
- 首版优先可靠性与可用性，不要为了视觉效果牺牲数据准确性。
